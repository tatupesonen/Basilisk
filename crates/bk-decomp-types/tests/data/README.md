# Test data for `bk-decomp-types`

| File | What it is | Provenance |
|---|---|---|
| `types_oracle.txt.gz` | 198,336 records: for `x86:LE:64:default:gcc`, `x86:LE:32:default:gcc`, `ARM:LE:32:v8:default`, `PowerPC:BE:32:default:default`, `AARCH64:LE:64:v8A:default`, `8051:BE:16:default:default` — the environment and data organisation, the core types, the result of each declaration of `../oracle/decls.txt` (layout, fields, bitfields, errors), the `compare` and `compareDependency` matrices, `getMatches` over the enumerations, `encode` of every type and of the factory, and queries over a grid of offsets and sizes; and `hashName` of 1,000 names. Read by `../oracle_replay.rs`. | Generated by `../oracle/regen.sh` from Ghidra commit `42db038f3c` (reference build objects, `scripts/build-reference.sh`), Apple clang 17.0.0, macOS AArch64 (Darwin arm64), 2026-11-14. The reference build uses `-fsigned-char`, so `hashName` sign-extends bytes as on x86-64 (ADR-021). |
| `types_orgs.txt.gz` | 296 records: environment and data organisation after `setupSizes` for every language/compiler pair Ghidra's `.ldefs` list (two V850 pairs fail to load in Ghidra itself and are recorded as errors). Read by `../oracle_dataorg.rs`. | As above. |

Host dependence: none of the recorded values involves floating point,
`long`, or unordered containers. Two things follow heap addresses in Ghidra
and are compared up to that order by the replay: the order of `<typegrp>`
(`dependentOrder`) and nothing else. `char` signedness is pinned by
`-fsigned-char`. Regenerating on x86-64 Linux should give the same table up
to the `<typegrp>` order.
