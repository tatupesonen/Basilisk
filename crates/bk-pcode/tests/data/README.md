|---|---|---|
| `opbehavior_cpp.txt.gz` | 87,176 evaluations of every p-code operation by Ghidra's C++ `OpBehavior` classes (`opbehavior.cc`, `float.cc`), one per line; the format is described at the top of `../oracle/opbehavior_oracle.cc`. Read by `../cpp_oracle.rs`. | Generated by `../oracle/regen.sh` from Ghidra commit `42db038f3c` (the same commit as the macOS reference build; the x86-64 build's `STAMP` records the commit as `unknown`) on the **x86-64 Linux reference build** (`scripts/build-reference.sh` in a container on the lent x86-64 box, `../reference-x86_64/`): GCC 14.4.0, Linux x86_64, 2026-11-14. Host-dependent results are x86-64's, which Basilisk follows (ADR-021): a NaN created by an operation is negative; with two NaN inputs `FLOAT_ADD`/`FLOAT_MULT` pass on the second's sign and `FLOAT_SUB`/`FLOAT_DIV` the first's; out-of-range `FLOAT_TRUNC` is `i64::MIN` (Basilisk saturates instead; see `../cpp_oracle.rs`). Made with the generator before its random draws were sequenced explicitly; the current generator reproduces this table's inputs line for line (checked on macOS AArch64), so a regeneration on x86-64 is expected to give identical bytes. It replaces a table made on macOS AArch64 (Apple clang 17, 2026-11-12). |
