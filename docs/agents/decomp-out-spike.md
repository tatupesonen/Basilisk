# Track `decomp-out-spike` (D16a) — status

Question: ADR-025 item 3c — can `PrintC`'s output be reproduced token for
token from a tree that is built first and printed afterwards?

**Answer: yes** (details below). The brief asked for the report in
`docs/research/decomp-out-spike/report.md`; the agent harness refused to
let me create that file, so the report is this document's section
"Report". The coordinator can move it.

## Report

### Answer

Ghidra's C printer can be split into a tree builder and a printer. A tree
built only from the printer's decisions prints back the exact sequence of
`Emit` calls `PrintC` makes, for every document of the corpus, in every
print mode tried, on both machines.

The tree is `PrintC`'s **emission tree**, not the block hierarchy. A block
printed twice in two modes (the condition of an `if`, once under
`no_branch`, once under `only_branch`) is two nodes. Each node carries the
facts `PrintC` read when it printed that part. The printer needs only the
tree and the printer options: no function, data-flow or symbol table.

### Evidence

A patched copy of the reference console logs, per document, `.tree` (entry
and exit of each structural `PrintC` method with the facts it read; every
push on the RPN stack; modifier and scope changes) and `.emit` (every call
on the `Emit` object). The prototype builds a tree from `.tree` alone,
prints it and compares with `.emit` call by call (ids renumbered by first
appearance).

Corpus: 93 data tests, 72 research fragments, 4 inputs of this spike: 169
scripts, each in five variants.

### The interleavings of plan 8.1

- **Prefix tokens.** `opReturn`, `opCbranch`, `opBranchind`, `opBranch`
  emit keywords then push operands (`printc.cc:539-610`, `773-803`). They
  are statement roots, entered with an empty RPN stack: statement nodes
  owning their expression. `emitBlockCondition` prints `&&`/`||` through
  `emitOp` on a fake entry (`printc.cc:2998-3005`); the node carries the
  opcode.
- **Parentheses.** `parentheses` (`printlanguage.cc:270-324`) uses the
  parent token, the child index and, for `hidden`, the grandparent: all in
  the tree. Recomputed with 0 differences.
- **Modifier flags.** The printer reads `no_branch`, `only_branch`,
  `comma_separate`, `flat`, `nofallthru`, `pending_brace` and recomputes
  them (0 differences). `force_hex`, `force_dec`, `print_load_value`,
  `print_store_value`, `falsebranch`, `negatetoken`, `hide_thisparam` are
  spent during pushes and appear as token/atom choices (or the "hidden"
  parameter fact). `bestfit`, `force_scinote`, `force_pointer` are never
  set in Ghidra.
- **`PendPrint`.** `hasPendingPrint` (`printc.cc:3043`) is true unless a
  line break reached the emitter since `setPendingPrint`
  (`prettyprint.cc:129-136`, `945-955`; `prettyprint.hh:1156`). The
  printer simulates it from its own calls; D16c's emitter needs Ghidra's
  pending-print behaviour.
- **`CommentSorter`.** Placement is the builder's; the tree holds comment
  groups at their places.
- **Declarations and types** share the RPN stack; they are expression
  trees under declaration nodes; never interleaved (0 on the corpus).
- **String and character constants** are read at push time
  (`printc.cc:1597-1807`); atoms carry the final text (64 string and 27
  character atoms in `orig`).
- **`flat`/`no_branch`/`only_branch`.** The tree has what each mode
  printed; flat mode prints the basic-block list (`printc.cc:2800`).

### Not proven

- Tokens `unary_plus` (never pushed; defined at `printc.cc:32`), `new_op`,
  `instanceof` (need Java constant-pool p-code; not tried).
- Nodes `constructor` (same), `opBranch` (needs an `only_branch` block
  ending in a plain `BRANCH`), `docSingleGlobal` (no caller in Ghidra).
- Flags `bestfit`, `force_scinote`, `force_pointer` (never set),
  `option_unplaced` (no caller of `setDisplayUnplaced`), `nofallthru` in
  flat mode (`printc.cc:2868-2884` is dead).

Reached this session through `inputs/` (all five variants): `orequal`,
`leftequal`, `boolean_xor` (`inplace.xml`; `boolean_xor` needs `option
togglerule bxor2notequal off`, otherwise `RuleBxor2NotEqual` makes it
`!=`), `remequal` (`remequal.xml`, RISC-V `remw`), a hidden non-first
`this` (`thisparam.xml`), the globals and types documents with struct,
enum, function-pointer and array declarations (`typesglobals.xml`).

### For D16b and D16c

**D16b** builds the emission tree with `PrintC`'s decision logic (which
ops print, in which mode, which comments where, which token and text each
push yields). Keep one node per print, not per block. Give header line
comments an explicit kind: the prototype tells the synthetic ones apart by
their text, which is fragile. Operator nodes carrying the printed strings
(or token plus a language table) keep the printer language-neutral: the
same printer printed `print language java`.

**D16c** can be accepted by printing logged trees: `.tree` is a complete
input, `.emit` the expected calls, the console output the expected text.
`printer.py` (about 1,000 lines) is a working model of the first half.
Conditions: a Rust reader for the formats in `bk-testkit`; logs produced by
`build-instr.sh` on the build host or checked in (`orig`: 6.3 MB, 0.5 MB
gzip); log and expected text from the same machine (float text differs
between them: data test `floatprint`); `print C types` text left out; the
text half (`EmitPrettyPrint`, `EmitMarkup`) was not checked by the spike.

### Ghidra defects

1. **`print C flat` prints wrong C** (any data test, e.g. `elseif.xml`,
   `print C flat` after `decompile`): labels print as a bare `:`
   (`emitLabel`, `printc.cc:3322`, calls `getFrontLeaf`, which returns
   null for a basic block, `block.cc:343-352`); branch targets print as
   annotation names, `goto Ram00000000001006f6;` (`printc.cc:597`);
   unconditional branches are never printed (`printc.cc:2844`; the goto at
   `printc.cc:2868` is unreachable in flat mode).
2. **`hideextensions` cannot be set**: declared (`options.hh:191`) and
   implemented (`options.cc:455`), never registered (`options.cc:98-135`);
   `option_hide_exts` is always true (`printc.cc:1648`).
3. **Confirmed: a hidden `this` that is not first leaves an empty slot.**
   `emitPrototypeInputs` prints the comma before testing for a hidden
   `this` (`printc.cc:2312-2317`); `this` is second when the first
   parameter is a hidden return pointer (`fspec.cc:3566-3578`).
   `inputs/thisparam.xml`, `print language java`: `big meth(big
   rethidden,,int4 y)`; with `this` last: `big meth2(big rethidden,)`.
4. **`print C types` crashes or prints stale layout.** `docTypeDefinitions`
   never calls `beginDocument`, `endDocument` or `flush`
   (`printc.cc:2482-2492`). As the first print of a session it crashes:
   `EmitPrettyPrint::print` reads `indentstack.back()` of an empty stack
   (`prettyprint.cc:702`; `decomp_dbg` under lldb; exit −11 in `decomp`).
   After another print it runs, but the indentation varies between runs
   (Mac) and the last line appears only with the next print. Reproduce:
   `typesglobals.xml`'s commands with `print C types` first.
5. **`print C types` writes invalid C**: struct fields separated by commas,
   enum values ended by semicolons (`printc.cc:2220-2224`, `2255-2259`);
   bit-fields left out (by reading: only `field` is iterated); any pointer
   type in the factory makes it fail with "Unsupported typedef"
   (`printc.cc:2466`).
6. **Hazard**: static `OpToken`s are shared by all printers and
   `adjustTypeOperators` rewrites `scope.print1`, `shift_right.print1`
   (`printc.cc:2424`, `printjava.cc:121`): two languages cannot print at
   once.

Withdrawn: the predecessor's note that `BlockIf::lastOp` reads component 2
of a two-component `if`. `block.hh:710` is `BlockIfNoExit::lastOp`, whose
block always has three components.
